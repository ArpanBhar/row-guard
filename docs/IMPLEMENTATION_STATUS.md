# Implementation status

Updated: 4 November 2026. This is an implementation snapshot, not a validation claim.

| Plan area | Current state |
| --- | --- |
| Daemon and PMU collector | Implemented for Linux x86-64 generic hardware events. Grouped per-CPU counter reads, multiplexing correction, and explicit degraded status are in place. On 3 November 2026, temporary `perf_event_paranoid=0` enabled a live system-wide `perf stat` run and RowGuard's collector; the daemon API reported `MONITORING`, valid quality, and live feature values. This setting is not persistent across reboot. |
| Features | One-second rolling execution, cache, IPC, miss ratio, and miss variability features are implemented. Uncore/LLC-specific event aliases and CPU-family profiles remain. |
| Detector | A packaged logistic-regression model is the default. It was trained from measured PMU windows across ten run-grouped sessions; two run-disjoint test runs and one later live run detected the Google tester without a benign incident in their measured controls. The earlier PMU rule remains an explicit `ROWGUARD_DETECTOR=rule` fallback. This is an experimental single-host model, not production validation. |
| Dashboard | Overview, feature graphs, incidents, evidence, and health with SSE updates and two-second polling fallback for Cloudflare Quick Tunnels. The UI and API share one origin and the dashboard assets are packaged with the daemon. Incident history shows top-CPU process candidates as unverified context. A clear-visible-log action hides prior incident/audit entries while preserving the signed audit chain. Headless Chrome checked desktop/mobile layouts and polling with SSE blocked. |
| Audit | Hash chain, signed Ed25519 checkpoints, local verification, separate verifier, and optional independent checkpoint receiver are implemented. Canonical JSON is a documented Python-specific v1 format; RFC 8785, key rotation, robust crash recovery, signed telemetry chunks, and retention proofs remain. |
| ML data | Local measured attack/control traces, a phase-aware corpus builder, run-grouped logistic training, a packaged artifact, incident-level evaluation, and a grouped comparison of logistic regression, random forest, XGBoost, SVM, and the fixed rule are implemented. Duke schema assessment, probability calibration, and cross-host transfer evaluation remain. See [ML_EVALUATION.md](ML_EVALUATION.md) and [MODEL_COMPARISON.md](MODEL_COMPARISON.md). |
| Hardware attack testing | Google's rowhammer-test was run in bounded sessions on the user's disposable Intel i5-11400H host. Two later prospective runs with the ML model active detected the tester and opened no incidents during baseline or memory-copy controls. One incident opened about 0.6 seconds after tool stop while its rolling window still contained attack data. No bit flip was reported. See [HARDWARE_EVALUATION.md](HARDWARE_EVALUATION.md). |
| Deployment | Example systemd unit is present. The wheel build was checked for the bundled dashboard and model. The README documents local and Cloudflare Tunnel viewing; a live tunnel has not been tested here. Full package installation, privilege validation under systemd, reboot/restart tests, and a remote receiver deployment remain. |

The dashboard's “ANCHORED” state means the configured receiver acknowledged the checkpoint. The verifier must independently fetch that receiver's latest checkpoint and use a separately pinned public key to assess rollback protection. No general Rowhammer-only or bit-flip detection accuracy is claimed from the bounded tool runs.
